# RFC 0007 — Contract-misuse defect corpus: ground-truth mutants + negative controls

- **Status:** 🚧 In progress — **P1 and P2 complete** (both landed 2026-07-29). P2 was the external-claims threshold and is fully shipped: 20 mutants / 18 controls across all five families, every operator the locked table promised, every depth label mechanically extracted, and all 37 transferable scripts green against real Postgres with `ground_truth=REAL`. **P3** (mechanical expansion toward 40–60) stays **demand-gated** per §6 — build-out follows measurement demand, not the reverse. The full landing log, including the findings that changed the design, is §10.
- **Scope:** a curated, labeled corpus of **known-bug** variants of Forze-built workloads ("misuse mutants") plus **known-correct** negative controls, with a declarative registry, a locked depth-labeling procedure, and a two-tier run policy (per-build smoke guard; offline statistical campaigns). Lives in `tests/support/misuse/` + a small `forze_dst` schema extension. This is the foundation the rest of the evidence program stands on: the fidelity-transfer experiment runs this corpus against real backends; the seed-statistics campaigns measure detection on it.
- **Related:** [artifacts/corpus.py](src/forze_dst/artifacts/corpus.py) (`RegressionEntry` — the reproduction schema the mutant record embeds); [tests/support/dst_flagship.py](tests/support/dst_flagship.py) (the picklable seed-target precedent); [oracle/replay.py](src/forze_dst/oracle/replay.py) (`minimize` — the 1-minimal reducer the depth extraction reuses); [scheduler.py](src/forze_dst/scheduler.py) (`PCTReorderer` / `SystematicReorderer` — depth semantics); `examples/recipes/` (`dst_payments`, `outbox`, `idempotency`, `order_fulfillment`, `two_phase_pricing`, … — the base workloads); RFC 0001 (conformance battery + `Conductor`); mutation-testing literature (Jia & Harman 2011 survey; Papadakis et al.) — we apply an established method to a new defect class, we do not claim a new method.
- **Origin:** the DST evidence-base plan (2026-07-22). Without ground truth no interesting question is answerable: *how good is a search strategy* (compared on what?), *is the mock faithful* (checked against which bugs?), *how many seeds suffice* (for which defects?). The corpus is the shared denominator. The `dst_payments` double-charge contrast is the prototype: one workload, one deliberate misuse, one invariant that catches it — generalized here into a systematic, labeled set. A sharpening fact from the 2026-07-22 git-history audit: the regression-corpus machinery (`RegressionEntry`, `save_regression`, the flagship `*_REGRESSION_SEEDS` tuples) is fully built and **entirely empty** — zero reproducing seeds are pinned anywhere in the tree. This corpus is what finally populates that machinery with ground-truth entries instead of waiting for accidental finds.

**Framing.** The mutants are **not** mutants of Forze internals. Each one is a realistic *misuse of a Forze contract by an application author* — dropping the rev guard, writing to the outbox outside the transaction, retrying without an idempotency key. That is the defect class the harness claims to catch, so that is the class the corpus encodes. Ground truth is by construction: we know each mutant contains exactly one seeded defect, and we know each control contains none. Secondary payoff, independent of any measurement: the smoke tier is a permanent regression suite over *the harness's ability to catch each misuse class*, and the operator table doubles as user-facing documentation of what DST does and does not catch.

---

## 1. Summary

~20 **misuse operators** in five families, each derived from a Forze contract and naming a real production bug class. Each operator instantiated against 2–4 base workloads → a corpus of 40–60 mutants at full build-out (P1 lands 6–8; P2 reaches the 15–20 that make external claims meaningful). Every instance carries: a 1-minimal reproducer, a killing seed (+ schedule seed + explore snapshot via `RegressionEntry`), a **depth label `d`** extracted by a locked mechanical procedure, its defect family, a port-observability flag, a transferability tier (for the transfer experiment), and a ground-truth field filled by the real-backend run. Negative controls ≥ 1:3 — unmutated bases plus *adversarial* correct twins (code that pattern-matches to a misuse but is correct). CI runs the smoke tier every build; statistical campaigns are offline `just` recipes.

## 2. The operator taxonomy

Each operator: what the mutant does, and the oracle expected to catch it. The full reviewed table (with per-operator literature/postmortem class citations — dual write, lost update, TOCTOU, …) is authored in `tests/support/misuse/OPERATORS.md` as part of P1; the taxonomy below is locked, individual operator wording may still be tuned there.

**T — concurrency & transactions**
- `T1 drop_rev_guard` — remove the optimistic-lock revision guard from an update. Oracle: `snapshot_isolation` / lost-update invariant.
- `T2 effect_before_guard` — move a side effect before the guarded write (the `dst_payments` double-charge). Oracle: workload conservation invariant.
- `T3 write_outside_tx` — hoist one write out of the transaction boundary. Oracle: atomicity/conservation invariant under crash fault.
- `T4 weaken_isolation` — declare a weaker `IsolationLevel` than the logic needs (write-skew-prone read-modify-write at `SNAPSHOT`). Oracle: `serializable` checker / invariant.
- `T5 check_then_act` — unguarded read-check-write over an aggregate (TOCTOU). Oracle: cardinality/uniqueness invariant.

**I — idempotency & retries**
- `I1 drop_idempotency_key` — remove the key from a retried command. Oracle: effect-count invariant under retry fault.
- `I2 retry_without_idempotency` — add a naive retry loop around a non-idempotent effect. Same oracle.
- `I3 ack_before_processing` — ack the message before the handler runs (at-most-once where at-least-once is required). Oracle: delivery invariant under crash.

**M — messaging**
- `M1 outbox_outside_tx` — publish to the outbox outside the aggregate transaction (dual write). Oracle: outbox↔state consistency invariant under crash-between.
- `M2 drop_inbox_dedup` — skip inbox deduplication. Oracle: effect-count under redelivery.
- `M3 missing_compensation` — delete a saga compensation step. Oracle: saga end-state invariant under mid-saga fault.
- `M4 nonidempotent_compensation` — compensation that double-applies on replay. Oracle: same, under compensation retry.

**D — distributed primitives**
- `D1 skip_lock` — bypass the distributed lock. Oracle: mutual-exclusion invariant (flagship dlock scenario).
- `D2 early_lock_release` — release inside the critical section. Same oracle.
- `D3 nonatomic_acquire` — check-then-set acquisition. Same oracle.
- `D4 ignore_remote_hlc` — drop the remote timestamp on HLC merge. Oracle: HLC monotonicity (flagship).
- `D5 nonmonotonic_clock` — read wall clock instead of HLC where ordering matters. Same oracle.

**N — data & multitenancy**
- `N1 drop_tenant_predicate` — remove the tenant filter from a query (cross-tenant leak; the tenancy matrix makes the oracle systematic). Oracle: tenancy-isolation invariant.
- `N2 stale_cache` — read-through cache with the write-path invalidation removed. Oracle: read-your-writes / staleness invariant.
- `N3 cursor_unbound_tenant` — cursor token not bound to tenant context. Oracle: tenancy invariant on paged reads.

Operators whose misuse Forze already **fails closed** at wiring or call time (e.g. some tenancy and isolation declarations) are still included where the failure mode is *silent* in at least one configuration; where the framework statically refuses the misuse, the "mutant" documents that refusal instead (a passing control with a note) — that too is evidence.

## 3. Corpus schema

`forze_dst/misuse.py` (schema only in `src`; instances live in tests):

- `MisuseMutant` (frozen attrs, kw_only): `mutant_id` (`"M1-outbox-order_fulfillment"`), `operator`, `family`, `base` (import target `module:attr`, picklable, `dst_flagship` style), `summary`, `expected_invariants: tuple[str, ...]`, `killing: RegressionEntry` (seed, schedule seed, explore snapshot, registry fingerprint — reuse, don't reinvent), `depth: int`, `depth_evidence: str` (the minimized choice vector, §4), `port_observable: bool`, `transfer_tier: TransferTier` (`CONDUCTOR | FAULT_ANALOG | NOT_TRANSFERABLE`), `ground_truth: GroundTruth` (`REAL | MOCK_ARTIFACT | UNDETERMINED` — starts `UNDETERMINED`, only the transfer experiment's real-backend run may set it), `notes`.
- `MisuseControl`: `control_id`, `base`, `summary`, `adversarial: bool` (True = deliberately misuse-shaped but correct: retry **with** key, release **in** `finally`, guarded check-then-act), `clean_band: tuple[int, int]` (the seed band asserted clean every build).
- `CORPUS: tuple[MisuseMutant, ...]` / `CONTROLS: tuple[MisuseControl, ...]` registries in `tests/support/misuse/__init__.py`, one module per family. A registry test enforces schema completeness (no mutant without a killing seed, a depth, and ≥1 expected invariant; control ratio ≥ 1:3).

Mutants are **hand-authored twin functions** next to their base, sharing setup via the base module — a deliberate copy of the `dst_payments` contrast pattern. No AST mutation engine (§7).

## 4. Depth labeling — the locked procedure

`d` must be operationally identical to the `depth` parameter of [PCTReorderer](src/forze_dst/scheduler.py) (d−1 priority-change points), or the seed-statistics bound comparison is apples-to-oranges. Locked definition:

> **d = 1 + the number of non-FIFO scheduling choices remaining in the 1-minimal reproducing schedule.**

Extraction is mechanical: reproduce the violation under `SystematicReorderer` with an explicit choice vector; run `minimize` ([oracle/replay.py](src/forze_dst/oracle/replay.py)) over the *set of non-zero choices* (a dropped choice becomes FIFO `0`) with `still_fails` = re-run at the reduced vector; the surviving non-zero choices are the ordering constraints; their count + 1 is `d`. The minimized vector is stored in `depth_evidence` so a reviewer can re-derive the label. Sanity cross-check (recorded, not a gate): PCT at `depth=d` finds the mutant at a materially higher rate than at `depth=d−1`. Mutants whose manifestation needs a **fault** (crash, redelivery), not an ordering, get the depth of their ordering component with the fault noted in `depth_evidence`; a pure-fault mutant (no ordering constraint) is `d=1`.

## 5. Run tiers

- **Smoke (every build, merge guard):** for each mutant, replay `killing` (exact seed + explore snapshot, `TestFlagshipCorpus`-style) and assert the expected invariant fires **and names the mutant's defect**; for each control, assert its `clean_band` produces zero violations. Fast (one seed per mutant + short bands), pytest-parameterized over the registries. This is the "harness catches misuse class X" regression suite and the user-facing capability documentation.
- **Statistical (offline):** `just dst-corpus-sweep` — wide bands over the corpus, feeding the seed-statistics campaigns and refreshing killing seeds after harness changes. Never in the per-build path.

## 6. Phasing

- **P1:** schema + registries + `OPERATORS.md` + 6–8 mutants covering ≥3 families (T2, T1, M1, M2, I1, D1 first — the highest-frequency production classes) + their controls + the smoke tier wired as a merge guard.
- **P2:** grow to 15–20 depth-labeled mutants + full control set; depth extraction tooling polished (`forze dst depth <mutant>` helper if the manual loop is annoying). *This is the external-claims threshold.*
- **P3:** mechanical expansion toward 40–60 (each operator × additional bases), gated on P2's mutants actually getting used by the transfer experiment and the statistics campaigns — build-out follows measurement demand, not the reverse.

## 7. Alternatives considered

- **A generic AST mutation engine.** Rejected for v1: 40–60 instances are cheaper hand-written than engine-built; hand-authored twins give unambiguous ground truth and readable diffs; the engine is a tool, and the plan's failure mode is building tools instead of measuring. Revisit only if P3 demand outgrows hand-authoring.
- **Mutating Forze internals.** Rejected: tests the wrong claim. The harness's promise is catching *application-level* contract misuse; framework-internal mutants measure the unit suite, not DST.
- **Reproducing named external systems' bugs (ZooKeeper, Cassandra, Jepsen corpora).** Rejected as out of applicability — those corpora are JVM distributed systems; we reproduce the documented *defect classes* over Forze ports and say exactly that. The per-operator citation column is the honest bridge.
- **Storing mutants as diffs/patches applied at test time.** Rejected: magic. Twin functions are grep-able, type-checked, and reviewed like any code.
- **Depth = "minimal number of events"** (the intuitive reading). Rejected: not the quantity in any published bound; locking the PCT-parameter-aligned definition is what makes the seed-statistics comparison legitimate.

## 8. Open questions

1. **Invariant-attribution strictness** — smoke asserts "the expected invariant fired"; should it also assert *no other* invariant fired first (sharper attribution, more brittle)? *Lean: expected-fired only; record others.*
2. **Where controls' adversarial twins live** — same family modules (adjacent to the mutant they mirror) vs a `controls/` module. *Lean: adjacent.*
3. **Killing-seed refresh policy** when a harness change invalidates seeds (fingerprint mismatch): fail the smoke tier (loud, forces re-mining) vs auto-quarantine with a warning. *Lean: fail loud — a silently quarantined corpus rots.*
4. **`forze_dst/misuse.py` vs keeping the schema in `tests/support/`** — schema in `src` lets user projects build their own misuse corpora against their apps (a real feature); test-only keeps surface small. *Lean: `src`, it's ~60 lines and the user-facing payoff is real.*

## 9. Decisions

| # | Decision |
| --- | --- |
| 1 | The corpus is **hand-authored broken twins of app-level workloads** — not a generic AST mutation engine (unambiguous ground truth and readable diffs beat tooling at this size) and not mutations of framework internals (that measures the unit suite, not DST) |
| 2 | Depth `d` is defined to be operationally identical to `PCTReorderer`'s `depth` parameter (d−1 priority-change points). Locking the PCT-aligned definition is what makes the seed-statistics bound comparison legitimate; "minimal number of events" is rejected |
| 3 | Depth labels are **mechanically extracted** (`forze_dst.depth.extract_depth`), never hand-asserted. The first mechanical run corrected every manual label in the corpus — exactly the failure mode locking the definition was meant to catch |
| 4 | Corpus oracles read **port state**, never trace markers: a marker recorded before a commit-time rev conflict is stranded by the rollback and would frame a correct control as broken. The one exception (`port_observable=False`) must be declared and gets a transferable sibling |
| 5 | The schema lives in `src` (`forze_dst.misuse`) so user projects can build corpora against their own apps; the instances live in `tests/support/misuse/` |
| 6 | Fingerprint drift **fails the smoke tier loud**, never auto-quarantines — a silently quarantined corpus rots into decoration |
| 7 | Negative controls stay ≥ 1:3 against mutants and include *adversarial* correct twins (code that pattern-matches to a misuse but is correct); a corpus without them measures nothing about false positives |
| 8 | Every mutant carries **two** workloads: the kill-fast smoke regime and a collision-pool campaign regime. The smoke regime is saturated (p̂ ≈ 1) by construction, and no scheduler or concurrency knob can de-saturate it — only the workload's pool size can |
| 9 | P3's expansion toward 40–60 instances is **demand-gated** on measurement actually consuming the P2 corpus; build-out follows measurement demand, never the reverse |

## 10. Execution log (2026-07-29)

**P1 landed.** Schema = `forze_dst.misuse` (`MisuseMutant` / `MisuseControl` / `MisuseFamily` / `TransferTier` / `GroundTruth`, plus `MisuseCase` — a factory-returned `(simulation, scenario)` bundle, added because corpus workloads need *explicit* scenarios: auto-derivation generates well-behaved inputs that rarely provoke the seeded defect). Instances = `tests/support/misuse/` (`transactions.py` / `idempotency.py` / `messaging.py` + `OPERATORS.md` with the locked 20-operator table): **6 mutants** (T1 blind-write, T2 charge-before-guard, T3 payment-outside-tx, T5 unchecked-reservation, I1 retry-without-key, M2 consumer-without-inbox) + **5 controls** (2 adversarial: row-before-guard-in-tx, retry-with-key), ratio 5:6 ≫ 1:3. All killing seeds mined (sweep over 400 seeds; entries carry seed + schedule seed + explore knobs + catalog fingerprint); **depth labels verified empirically** — every d=2 mutant is clean at `concurrency=1` over 200 seeds, every d=1 mutant kills there (`depth_evidence` records this; mechanical 1-minimal extraction = P2). **Authoring rule discovered and codified**: corpus oracles read *port state* (row counts via `observe`), never trace markers — a marker recorded before a commit-time rev conflict is stranded by the rollback and would frame a correct control; the one exception is T2, whose seeded misuse *is* the non-transactional external effect (hence `port_observable=False`, `NOT_TRANSFERABLE`, with T3 as its transferable sibling). Smoke tier = `tests/unit/test_forze_dst/test_misuse_corpus.py` (17 tests, ~1 s, every build): killing-seed replay with sharp invariant attribution + fingerprint-drift fails loud (OQ3 resolved: fail loud), control clean bands, registry completeness (ratio, families ≥3, adversarial ≥2). OQ4 resolved: schema in `src`. M1 (outbox-outside-tx, needs crash fault) deliberately deferred to P2 as the highest-value remaining operator; D/N families P2+. **P2 scope grew by one measurement-driven requirement (from the seed-statistics pilot, 2026-07-29): campaign-regime workloads.** The kill-fast smoke workloads are *saturated* (p̂ ≈ 1 per seed under every strategy — with two racy ops in flight the adverse interleaving is near-certain, and act/concurrency knobs cannot change that). P3-grade statistics need each mutant to also carry a **collision-pool workload** (the race fires only when two ops draw the same entity from a pool of size P, making p̂ ≈ 1/P tunable) — a second scenario per mutant, recorded in the registry alongside the smoke regime.

**P2 first slice landed 2026-07-29 — the two statistics-gating pieces:** *(1) Mechanical depth extraction* (`forze_dst.depth.extract_depth`): find a violating interleaving of a fixed workload via the systematic explorer, greedily zero its choice vector to 1-minimal, d = 1 + surviving non-FIFO choices, evidence = the vector + workload seed (re-derivable). **First run corrected the corpus's own labels**: all four T-family manual d=2 labels are wrong — the 1-minimal schedule is *empty* (plain FIFO at concurrency≥2 already violates; the adverse interleaving is the default cooperative schedule), so **every P1 mutant is d=1**; the manual labels had conflated workload concurrency (two in-flight ops are required — still true) with scheduler ordering constraints (zero are needed). Registry updated with mechanical evidence strings; smoke tier now asserts every label is mechanical. Exactly the failure mode locking the definition was meant to catch — and the tool caught its own corpus first. *(2) Campaign regimes*: `MisuseMutant.campaign_base`/`campaign_explore` + pooled factories for all six mutants (pool P=16; T: act 2 × concurrency 2, I/M: act 2 sequential); the campaign runner prefers the regime automatically (fingerprint gate spans regimes — same catalog). **De-saturation verified by measurement**: pilot regenerated, p̂ ≈ 0.05–0.07 per cell (predicted 1/P = 0.0625), medians 10–17 seeds, honest quartile spreads; strategies statistically indistinguishable at N=100 — *theory-consistent*, since PCT's depth parameter should buy nothing on d=1 bugs. **Still open in P2**: growth to 15–20 mutants (M1 outbox-outside-tx + I3 need the crash fault; D/N families), and — new, from the depth finding — the d-axis is degenerate (all d=1): the p̂-vs-d experiment needs mutants whose defect *genuinely* requires rare reorderings beyond the default cooperative interleave (narrow multi-step windows), an authoring requirement no pool knob can satisfy.

**d-axis un-degenerated 2026-07-29: `T3-torn-activation`, the corpus's first genuinely depth-2 mutant** (7 mutants, 6 controls). The authoring method that worked: symmetric two-op races are *structurally* d=1 (FIFO lockstep is itself racy — all reads land before all writes), so depth requires a **phase-aligned window lockstep misses in both spawn orders**. Instance: provision = create + activate in *separate transactions* (a second `T3 write_outside_tx` instance, instantiated deep) with a reader whose profile-read is phase-padded (`SERVE_PADDING=2`) so FIFO is clean both ways; only an overtake (one non-FIFO choice) reaches the torn created-but-not-ready window. **Mechanically verified**: `extract_depth` → `choices=(0,0,0,1)`, d=2; padding 0–1 degenerates to d=1, padding ≥3 makes the window unreachable within 40k systematic runs (a d=3 instance needs a different construction — still open). Naturally de-saturated (p̂ ≈ 0.26 under random — no pool needed); atomic-provision control clean; **the transfer differential caught a real authoring bug on its first run** (the control's verdict counted `torn` rows globally — a self-isolation violation invisible on the mock's fresh state, flagged as MOCK_WEAK on Postgres's persistent tables; fixed by keying `serve_log` to the profile) and then went green: mock ≡ real Postgres on all 12 scripts, `ground_truth=REAL` licensed. Pilot regenerated with the d=2 rows (median 3 seeds, p̂ ≈ 0.25–0.27 per strategy).

**Crash-fault operators landed 2026-07-29 — corpus now 9 mutants / 8 controls.** `MisuseCase.crash: CrashPolicy` threads the crash → restart → recovery scenario through every corpus runner (smoke, campaigns, and *controls run under the same crashes* — an atomic twin is only a control if the crash can't frame it). **M1 `outbox_outside_tx`** (`M1-dual-write-shipment`): state and its outbox event in separate transactions; the crash between the commits strands state whose event never leaves; the atomic outbox-pattern control is clean under the identical policy. **I3 `ack_before_processing`** (`I3-ack-before-processing`): the ack commits before the effect; the crash in the window plus the redelivery's "already done" skip makes the loss *permanent* — the full at-most-once production story; the effect+ack-in-one-tx control recovers via redelivery. Both d=1 with `fault:` evidence (crash-triggered, no ordering constraint; systematic extraction is faultless by design — the label rule is now two-pronged: `mechanical:` for ordering bugs, `fault:` for crash bugs). **`FAULT_ANALOG` transfer exercised for the first time**: the analog is deterministic — the simulated crash maps to the session *abandoning* after the first commit (a dead process holds no further writes), the control's crash to an abort raised inside its single transaction — and the PG differential is green over all **16** scripts (8 transferable mutants — 9 minus the `NOT_TRANSFERABLE` T2 — plus all 8 controls; both crash mutants DETECTED on real Postgres, both crash controls CLEAN including the redelivery-recovers path), licensing both `ground_truth=REAL` fills. Pilot regenerated: M1 p̂ ≈ 0.41–0.53, I3 p̂ ≈ 0.35–0.39 — naturally de-saturated by the crash-point lottery. **Remaining in P2**: I2/T4, D family (dlock seam), N family (tenancy seam), a d=3 construction, growth toward 15–20.

**D/N families landed 2026-07-29 — corpus now 13 mutants / 11 controls (the 15–20 band is within one slice).** The D family runs over a **lease-row lock protocol** (a DB-backed lock: atomic acquire = unique-id create in its own transaction; the critical section is a read-modify-*blind*-write, so only the lease protects it; the control holds the lease for the run — no release API needed): **D1 `skip_lock`** (`D1-skip-lock`) and **D3 `nonatomic_acquire`** (`D3-nonatomic-acquire`, check-then-set re-deriving T5 at the lock layer), both mechanically d=1. **N1 `drop_tenant_predicate`** (`N1-drop-tenant-predicate`, tenant-as-field: the un-filtered browse counts the other tenant's rows) and **N2 `stale_cache`** (`N2-stale-cache`, write-path invalidation dropped — the *writer's own* read-through sees the stale version, the final-state-safe read-your-writes observable). N1/N2 carry a new registry note class, **deterministic manifestation**: detection is not seed-dependent (p ≈ 1 legitimately), so they contribute breadth and transfer ground truth, not detection-time discrimination. All four transferred: PG differential green over all **23** scripts (one Conductor-weave fix caught by the mock-vs-mock parity tier: D3's both-checks-before-either-creates needs its own checkpoint), `ground_truth=REAL` licensed; pilot regenerated (3933 records). **Remaining in P2 now**: I2, T4, D2 (needs lease release/delete), D4/D5 (HLC/clock seam), N3 (cursor tokens), a d=3 construction, +2 mutants to reach 15.

**I2 + T4 + D2 landed 2026-07-29 — corpus at 16 mutants / 14 controls: the 15–20 band is reached.** **T4 `weaken_isolation`** (`T4-weakened-oncall`): the Fekete on-call rota — read-both/write-own at a *declared* SNAPSHOT; the control is byte-identical at SERIALIZABLE and backs off on the SSI abort (`is_serialization_conflict`, the same class the differential compares). Killing at seed 0/`_CONCURRENT`; clean at concurrency=1 (overlap required, as the operator predicts); campaign = 16-rota pool with **p_trigger = 1/(2·pool)** (same rota AND distinct doctors — special-cased in the analyzer; measured p̂ ≈ 0.03 ≈ 1/32, p̂_sched = 1.00 exactly). **I2 `retry_without_idempotency`** (`I2-naive-retry-loop`): a naive in-handler retry loop whose non-idempotent receipt commits in its own transaction *before* the per-order ack that conflicts for the duplicate — the re-run mints receipt #2; the control runs the *same loop* with a command-keyed receipt. Kills sequentially (d=1, empty vector at concurrency=1, like I1); campaign = `_SEQ_CAMPAIGN` (p̂ ≈ 0.054 ≈ 1/16). **D2 `early_lock_release`** (`D2-early-lease-release`): the lease dropped after the read, before the write; spin-acquiring waiters (3 attempts) enter the release→write hole. **Two findings on the way in:** (1) the release had to be `kill` — the document `delete(pk, rev)` is *soft*-delete and raised `internal` on the lease model, which silently made the race unreachable (2400 random seeds + 40k systematic runs, zero kills) until the probe isolated it; (2) once fixed, D2 is mechanically d=1 with an *empty* vector — FIFO lockstep itself walks the waiter into the hole — and it is **the corpus's first cell where PCT visibly beats random** (p̂ 0.92–0.95 vs 0.74; the overtake into the window is exactly what priority scheduling manufactures). Naturally de-saturated, no pool. All three transferable: 29/29 scripts green on real Postgres first run (mock-parity tier had already verified the Conductor weaves), `ground_truth=REAL` licensed; new PG tables `receipts`/`submissions` (field renamed `order`→`booking` — reserved word, the `guest` lesson)/`oncall`; predictor mapping grew to 8 mapped (T4→`write_skew`, D2→`lost_update`, I2 outside the domain) — contingency now [[8,0],[0,0]], still the degenerate branch. Pilot regenerated (4842 records), W3: 26 rows, 0 violations, all measured-n/k. Remaining in P2: D4/D5 (HLC/clock seam), N3 (cursor tokens), the d=3 construction.

**d=3 landed 2026-07-29 — `T3-double-torn` (17 mutants / 15 controls) — with the program's sharpest methodological finding.** Construction: provision creates+activates TWO profile halves in four separate transactions (two sequential torn windows); the serve composes from both, degrades gracefully on one torn half ("partial"), and blacks out only when its two reads land in BOTH windows — which requires the writer stalled at two separated points. Found by a (P1, P2) pad grid sweep over the unpruned systematic explorer; the winning alignment is `PAIR_SERVE_PADDING=2` with adjacent reads. **Verified beyond the locked 1-minimal procedure**: FIFO clean, canonical (pruned) `extract_depth` yields `(1, 0, 0, 0, 1)` → d=3, and **every single-nonzero-choice vector over the tick space was exhaustively refuted** — no depth-2 schedule kills, the strongest depth label in the corpus. **THE FINDING — mechanical depth and PCT depth measurably diverge at d≥3**: the tick-promotion model (deviations from cooperative round-robin FIFO) needs 2 choices, but PCT's priority-stall model (deviations from run-to-priority) needs ~3 change points (four priority segments) for this bug — measured per-seed p̂: **random 0.118 ≫ pct-d4 0.03 > pct-d3 0.010 > pct-d2 0.006**, a full inversion of the PCT ladder, because the fine-grained alternation this bug wants is *closer to random's baseline than to PCT's*.
