# T-0061 — Fail-closed production posture

Executing [RFC 0061](../rfcs/0061-production-posture.md) P1–P2 on `feat/production-posture`.
P3 (CLI entry point, further rules) stays demand-gated; exemptions ship now, as far as P2's
escalation needs them.

## Plan

- `forze/application/execution/posture.py` (new): the rule kinds (`RequireSet`, `RequireHttps`,
  `DevValue`, `LoopbackHost`), `Exempt`, `ProductionPosture` (carrying the app's settings),
  `WiringFinding` (the declaration-time finding every reporter uses), the `PostureAware` protocol
  a deps module implements to report its configs' safety findings, and the shipped default rule.
- `execution/deps`: `DepsRegistry.freeze()` collects module findings; `FrozenDepsRegistry` and
  `FrozenDeps` carry them, so both gates reach them.
- `execution/operations/wiring.py`: `WiringReport.findings`; `check_wiring(..., posture=...)`.
- `execution/runtime.py` + `assemble.py`: `posture=` evaluated at construction, refusing boot.
- `forze_http`: the cleartext-credentials check reports a finding through `HttpDepsModule`, so it
  warns without a production posture and refuses under one.
- Batteries: each rule kind; key-only errors (a planted secret absent from the error and the
  captured log); silence is production; non-production is inert and the shipped warning still
  warns; both gates, `build_runtime` refusing without `check_wiring`; an unresolvable path; the
  escalation both ways; an exemption.
- Docs: a running-in-prod page (declaration, default rule, both gates, "an unset environment is
  production", the migration note); changelog.

Four decisions the RFC left unsettled were put to the maintainer before code; their answers are
entries 3–6.

## Self-audit — 2026-09-28

Scope: the whole branch against `main` — 2 commits, 14 files, ~1.3k lines (source, tests, docs,
changelog, nav), plus the fixes below. Re-read RFC 0061 §5–§7 and §11 first.

**Sabotage, then coverage.** 24 mutants over `posture.py`, the wiring report, the runtime gate,
the registry and frozen deps, and the HTTP module and predicate: all killed. The code read that
followed still found three defects the sweep could not have imagined, and patch coverage then
named five untested claims. Every fix below was reproduced red first and its mutant killed after.

Findings, most severe first:

1. **The shipped marker scan missed values it promises to read** (fixed). "A `_dev_only` marker
   anywhere in the settings" skipped a value inside a list of models or of mappings, and any key
   kept by `extra="allow"`: `_texts` yielded nothing for a model or a mapping, and `_leaves` and
   `_resolve` read only declared fields. The same gap let a rule pointed at a group — a nested
   model or a mapping — pass without reading anything under it. Fixed where every rule routes
   through: `_texts` reads a group's leaves, `_fields` includes the extras.
2. **An unparseable URL crashed the posture instead of being judged** (fixed). `urlsplit` raises
   on a netloc with an unmatched or non-address bracket — an unencoded password can hold one — and
   its error can quote part of the netloc, so the boot failed with a parser error rather than a
   refusal, against D-2's intent. `_split` returns `None`; unparseable is not https and names no
   loopback host.
3. **`check_facade_factory_wiring` could not carry a posture** (fixed). The convenience sibling of
   `check_wiring` took no `posture=`, so an application checking through it never got the early
   gate. It passes one through now.
4. **§6's "the shipped warnings still warn" was unasserted** (fixed). The legs named
   `…_only_warns` built the runtime and checked nothing; they now assert the cleartext warning
   fires once, without a posture and under a non-production one, and a mutant silencing it dies.
5. **Coverage-named claims with no leg** (fixed): `RequireSet` over an empty collection, blank
   bytes and a zero; a pydantic URL-typed field (not a `str`); a `SecretBytes` marker; a path
   through a scalar value; an `Enum` environment. `is_production` now reads the environment
   through `_texts` too, dropping its own `Enum` branch.

Checked and found sound: the no-values leg's log half is not vacuous — a planted
`logger.warning(..., dsn=...)` in `enforce` fails it (the first attempt at that mutant was an
`ImportError`, not a kill, and was redone). Patch coverage 100% of added lines after the fixes.

Residue I would still distrust: `LoopbackHost` reads only the host `urlsplit` finds, so a
multi-host DSN (`postgresql://a,localhost/db`) is not recognised; the default scan reports a
value found inside a list at the list's path, not the element's. Neither is claimed by the docs.

group applies to every value under it, which `RequireSet` does not do — it asks only that the
