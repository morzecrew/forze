# T-0061 — Fail-closed production posture

Executing [RFC 0061](../rfcs/0061-production-posture.md) P1–P2 on `feat/production-posture`.
P3 (CLI entry point, further rules) stays demand-gated; exemptions ship now, as far as P2's
escalation needs them.

## Plan

- `forze/application/execution/posture.py` (new): the rule kinds (`RequireSet`, `RequireHttps`,
  `DevValue`, `LoopbackHost`), `Exempt`, `ProductionPosture` (carrying the app's settings),
  `WiringFinding` (the declaration-time finding every reporter uses), the `PostureAware` protocol
  a deps module implements to report its configs' safety findings, and the shipped default rule.
- `execution/deps`: `DepsRegistry.freeze()` collects module findings; `FrozenDepsRegistry` and
  `FrozenDeps` carry them, so both gates reach them.
- `execution/operations/wiring.py`: `WiringReport.findings`; `check_wiring(..., posture=...)`.
- `execution/runtime.py` + `assemble.py`: `posture=` evaluated at construction, refusing boot.
- `forze_http`: the cleartext-credentials check reports a finding through `HttpDepsModule`, so it
  warns without a production posture and refuses under one.
- Batteries: each rule kind; key-only errors (a planted secret absent from the error and the
  captured log); silence is production; non-production is inert and the shipped warning still
  warns; both gates, `build_runtime` refusing without `check_wiring`; an unresolvable path; the
  escalation both ways; an exemption.
- Docs: a running-in-prod page (declaration, default rule, both gates, "an unset environment is
  production", the migration note); changelog.

Four decisions the RFC left unsettled were put to the maintainer before code; their answers are
entries 3–6.
