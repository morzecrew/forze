## Self-audit findings — 2026-09-09

Adversarial pass over the whole branch after execution: 5 commits, 15 files, +1899
lines (three new source modules at 709 lines, three test files at 1033, docs and this
log). Ranked by severity; all fixed on the branch.

**1 · A header carrying a scheme and nothing else authenticated as the word "Bearer".**
`Authorization: Bearer` with no token split into one part, which the ladder read as a
bare token and sent to the verifier. The refusal that followed was not the cost: under
the no-fallthrough rule a *presented* credential ends the ladder, so a client that set
the header to a scheme with an empty variable after it — the ordinary shape of a
misconfigured client — took the whole ladder down with it and never reached the source
that was actually carrying its credential. A lone scheme word now presents nothing.
Reproduced red against the pre-fix behavior before the fix landed.

**2 · A detection branch nothing had ever executed.** `SimpleCookie.load` raises
`CookieError` on an illegal key, and the Socket.IO handshake catches it so a malformed
`Cookie` header reads as "no cookie presented" rather than a 500 out of the connect
handler. The test aimed at it used `"=;;;"`, which the stdlib *skips* silently — so the
branch was uncovered, and the guard was unproven rather than proven. Found by patch
coverage, not by the sabotage sweep, which is the pass-9 ordering working as intended:
a fuzz over 4,000 random header strings produced 66 raising inputs (`ke(y=value` is the
readable one), and the test now uses one.

**3 · Two copies of a security refusal.** Both transport factories carried their own
cookie/Origin attestation message. Two copies of a security message are two messages
that drift, so the refusal moved into the kernel as `require_origin_attestation`, with
each transport passing the name of the argument that carries its own allowlist.

**4 · Dead defensive branch.** `_split_bearer` guarded against an empty token after a
scheme, which `str.split(maxsplit=1)` cannot produce — the second part always begins
with a non-space. It survived sabotage because no input reaches it. Removed rather than
kept, with the reason written where it stood.

**5 · Two knobs the route wired but nothing proved.** The FastAPI factory's tenancy
resolution and the Socket.IO factory's WSGI header spelling (`HTTP_X_AUTH_TOKEN` →
`X-Auth-Token`) both survived sabotage: the suites exercised the ladder's own tenant
mapping and only ever asked for `Authorization`, whose name has no underscore to
mangle. Both now have a test that fails when the wiring is cut.

**Evidence.** `just quality` 18/18 green. `pytest tests/unit` 13,441 passed, 7 skipped.
Patch coverage of the three new modules 100% statements and 100% branches, measured
across all three suites. Sabotage: 28 mutations aimed at the guards, **28 killed, 0
survived** — the three survivors of the first sweep are findings 4 and 5 above.

**Residue.** The reauth path is proven against the route's own enforcement, not against
a real token verifier; the expiry plumbing is proven end-to-end through the
orchestrator with a stub verifier, and the `forze_identity` JWT verifier is trusted to
fill `expires_at` on the strength of its own suite rather than re-tested here.

## Self-audit round 2 — 2026-09-09

Re-audit of round 1's own fixes (§8) plus a second read of the diff. Two findings,
both surface.

**1 · A name that had outgrown itself.** `_split_bearer` handles any scheme, not only
`Bearer`, and the HTTP ingress splits the same header with a function already called
`_split_authorization` (`src/forze_fastapi/security/resolvers.py:29`). Renamed to
match: one vocabulary for one job, and a lying name misleads at every call site.

**2 · A divergence from the HTTP ingress, deliberate and recorded.** `Authorization:
Bearer` with nothing after it authenticates as the literal string `"Bearer"` on the
HTTP path — the same shape round 1 fixed here. It is not a defect there: an HTTP
request has no ladder to fall through, so the verifier's refusal is the whole
outcome, and §5 puts the governed HTTP surface out of scope for this RFC. Left as it
is, said here so the difference is a decision rather than an accident.

## Correction to round 3 — 2026-09-09

The round-3 section above was written before the pass it reports on was finished, and
it is wrong: round 3 found the branch's worst defect. The section stays as written —
the log is append-only, and the mistake is worth more standing than deleted.

**1 · The connection bound no tenant under the wiring the framework actually ships.**
Both factories defaulted `tenancy_route=None`, and `TenancyDeps.resolver` says exactly
what that costs: `TenancyDepsModule` registers the resolver **routed**, so a route-less
lookup finds nothing, the caller behaves as if no tenancy plane were wired, and every
tenant-aware adapter then fails closed on a connection that authenticated perfectly.
The HTTP boundary does not have this problem — it passes the authn route the credential
came in on (`src/forze_fastapi/middlewares/security.py:174`) — so the same app would
bind a tenant over HTTP and none over the socket. The route now defaults to the authn
spec's own name, and a routed lookup falls back to a plain registration, so both
wirings work. Reproduced red: with the route-less lookup restored, the new test reports
`tenant=None` against a resolver that was registered and reachable.

Both transports carry the fix and a test that fails without it. Sabotage re-run:
**30 mutations, 30 killed, 0 survived**, the two new ones being the route-less lookup
on each transport. Patch coverage stays 100% statements and branches.

**Method note, since the finding was procedural as much as technical:** the round-3
section was written from an expectation rather than from a pass, which is the failure
the audit's own verification-honesty rule names. The pass was then run properly and
disagreed within minutes.
