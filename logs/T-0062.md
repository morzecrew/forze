# T-0062 — Log redaction reach

Planning [RFC 0062](../rfcs/0062-log-redaction-reach.md)'s one phase: the root-attachment rule, the
`redact_unnamed` flag, its warning, the four-leg battery and the two doc sentences. **Stopped at
the readiness gate before any code.** Three decisions the plan needs are not settled by the spec,
and two of them undercut the premise its `LOCKED` rows rest on.

## Plan

- `forze/base/logging/configure.py`: when `logger_names` is non-empty, `configure_logging` also
  attaches a redacting handler to the root at the same level (D-2), unless
  `redact_unnamed=False`, which warns once (D-3). The names it attaches get `propagate=False`
  (D-5).
- Battery per §6: default path unchanged, narrowed path scrubbed (and not before), the opt-out
  warns once, single emission, message and extras.
- Docs: two sentences at `logger_names` in the logging page; changelog.

## Decisions the spec does not settle

Three are load-bearing, so this stops at the readiness gate for the author.

1. **The motivating logger is not reached by the rule.** §2's case is uvicorn's access log. But
   uvicorn's own logging config gives `uvicorn.access` its own handler and `propagate: False`.
   A handler on the root never sees its records, so the rule as written does not redact the log
   that motivates it. What does reach it is attaching the name explicitly, which
   `attach_foreign_loggers` / `bootstrap_logging(third_party=...)` already do with the scrubbing
   formatter. The gap may be documentation, not attachment.
2. **"At the same level" changes what every narrowed app prints.** Today an app that narrows gets
   nothing from unlisted loggers below WARNING. Python's last-resort handler emits WARNING and up
   only, as `configure.py`'s own comment says (`src/forze/base/logging/configure.py:296-302`). A root handler at the app's level would start
   emitting every unlisted dependency's INFO. That is a volume change the spec does not weigh;
   the alternative is a root handler at WARNING, which scrubs what already escapes and adds
   nothing.
3. **The narrowed path is the common path, not the exception.** `bootstrap_logging` always
   passes a non-empty list: the core logger names plus any integrations
   (`src/forze/base/logging/configure.py:394`). So every app using the
   one-call setup narrows, and the change lands on nearly every deployment. §4's "no behaviour
   change for the default path" holds only for a direct `configure_logging()` call with no
   names.
