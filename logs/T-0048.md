# T-0048 · Derived read fields

Executing RFC 0048 against branch `feat/derived-read-fields`.

**Drift count: 0.**

Where building this disagreed with the design for it, written at the moment it
happened. Nothing here is revised afterwards to agree with what was later
settled, and nothing here has been folded back into the RFC's own text. The rows
proposed below are put forward for the author to accept or refuse; execution does
not write them into a decision table itself.

| Class | Test | Meaning |
|---|---|---|
| `discovery` | Could not have been known before code existed | Healthy — the spec was right to be silent |
| `spec-gap` | Could have been known; the spec was silent or at the wrong altitude | The design process missed something |
| `drift` | The spec covered it and it was built otherwise anyway | **A defect** |
| `irreducible` | No amount of design settles it | Stop and spike |

## Audit findings — 2026-09-10

**A-1 · The nullable-key check conflated "has a default" with "may be None".**
The first cut used `FieldInfo.is_required()`, which is false for `note: str = ""` — a
defaulted, non-nullable field and a perfectly good join key. It was refused. Caught by
the itself-derived guardrail's own test, which happens to use that field, so the defect
surfaced as a wrong error message on an unrelated case rather than as a missing refusal.
Fixed with `_admits_none`, which reads the annotation. The lesson is the reusable half: a
guard about *nullability* must read the annotation, never the default, and the two are
one method call apart.

**A-2 · Two behaviours were claimed in a docstring and proven by nothing.** The sabotage
sweep survived both: the factory's cross-tenant refusal, and the routing of a derived read
through the active transaction's view. The second is the sharper miss — the docstring says
"a source row joined outside the overlay would let a snapshot transaction observe a sibling
write it must not see", which is a specific claim about isolation with no test behind it.
Both now have one, and both sabotages are killed.

**Sweep: 13 mutations, 13 killed.** Two of the original twelve were invalid and were
redone — one whose anchor no longer matched after formatting, and one that raised at import
rather than changing behaviour, which would have counted as a kill for the wrong reason.

**A-3 · The derived field was settable on a create command and nothing refused it.**
`materialized` carries exactly this rule — a value the backend produces is not one a
caller sets — and the derived declaration did not. A create command could name the joined
field, and no write path could store it. Found by asking what the *write* side does with a
declaration that only ever describes reads, which the sabotage sweep would not have
reached because no test named the shape. Refused now, with the sibling's wording.

**A-4 · §5.3's divergence bound was argued and not measured.** The design's real risk is
two implementations of one read — a view and a hand-rolled join — and the RFC bounds it by
saying the differential covers it. There was no differential. There is now
(`tests/integration/test_forze_postgres/test_pg_document_derived_read_fields.py`): two
tables and a real view, read through the Postgres gateway and through the mock with the
same spec, asserted equal. The second case records the one place they *do* differ — an
inner-join view omits a row whose source is gone where the mock refuses the read — so the
agreement is not read as total.

**A-5 · Residue.** A first cut of that integration test carried an `if False else None`
expression left over from an edit, which ran green and asserted nothing about the case it
named. Removed, and the test now performs the delete and asserts both failures. Worth
recording because it passed: a test whose subject is a divergence is exactly the test that
can pass while measuring nothing.

**Sweep, round two: 17 mutations, 17 killed.** The four new ones cover the settable-command
refusal, the nullable-key refusal, `_admits_none` reading the annotation rather than the
default, and the malformed-key guard.

**What the schema says, in numbers.** Across the 15 repeatable view migrations:

| Projection shape | Count | Served by P1 |
|---|---|---|
| scalar one-hop (`c.code AS catalog_code`) | 13 | **yes** |
| nested reference object (`entity_json(c) AS catalog`) | 27 | no |
| arithmetic / `COALESCE` aggregate / `CASE` | ~79 | no, and no declaration would |

The 27 nested fields are all `ReadEntityReference` — `id`, `rev`, `name`, `number_id` — built by
`public.entity_json` and five siblings that project wider subsets (`detail_json` adds five
fields, `status_aware_json` adds `status`, `logical_slot_json` is a different shape
entirely). **Twelve are required**, and a required field is exactly what makes the mock
refuse the row.

Of the four fields the origin report named, `catalog_code` is the scalar and `supplier`,
`order` and `group` are all nested objects.

**A-6 · A marked field left unsupplied escaped as a raw pydantic `ValidationError`.**
Found by a test that asserted the wrong exception type and so reported the right defect:
the read refused, but with a missing-key error naming nothing about the declaration that
put the field beyond the write path. Now `mock.document.derived_unsupplied`, naming the
three ways out (seed it, resolve it, make it optional). The reusable half: when a new
declaration moves a field outside the normal path, the failure it causes has to name the
declaration, or the feature is discoverable only by reading the source.

**Sweep, round three: 9 mutations, 9 killed.** One survivor first — the requiredness
filter in the presence check, so an *optional* marked field with no value was untested;
absence is what `None` is for, and nothing proved the check left it alone.

**A-7 · A determinism claim that only the default made true.** The seeder now mints the
id for a spec with derived values, and the comment justified it with "the seeded entropy
source above is bound for the duration". That binding is conditional — `apply_seed` enters
it only when `plan.instant is not None` — and the default entropy source is
`SystemEntropySource`, so on `instant=None` the sentence was false. The passing
determinism test did not catch it, because `SeedPlan.instant` defaults to a pinned
instant: the assertion was true for the wrong reason, and would have stayed true while the
comment misled anyone reading it. Comment corrected, and a second case pins the opt-out so
the first cannot be read as unconditional.

The rule worth keeping: **a determinism claim has to name what binds it.** "Deterministic
because a source is bound above" is unverifiable at the call site when the binding sits
behind an `if`, and a test run under the default proves only the default.

**A-8 · Four type errors the unit suite could not see.** `mypy` caught what 13826 passing
tests did not: `spec.field.strip()` on a `str | None` (narrowed once now, since the triple
is all-or-nothing by construction); an unannotated lambda converter, replaced by a named
function; and the seeder reaching `_store()` through the *port protocol*, which has no such
method — now an explicit `isinstance` on the mock adapter with a refusal for anything else.
The last is the one worth keeping: the seeder is mock-only by nature, and reaching a
private method through a public protocol type-checked only because nothing asked.

## Residue at hand-off — 2026-09-11

Two claims I made in conversation that the code does not support, corrected here rather
than left to be discovered:

**The marker does not unblock `forze_dst`.** I said generation would fill required derived
fields, reasoning from `SpecSeed.count` producing shape-correct values. It generates from
the *create command*, which a derived field is refused on, so `SpecSeed(spec=…, count=2)`
with a required marked field refuses at the first read
(`mock.document.derived_unsupplied`). Probed, not assumed:

```
SpecSeed(spec=ORDERS, count=2)  # no derived= supplied
→ CoreException(mock.document.derived_unsupplied)
```

Generating a value from the *read model's* annotation is the missing piece, and it is what
a simulation needs, because nobody writes a `SpecSeed` for one. Not built.

**Derived values are per-spec, not per-row.** `SpecSeed.derived` applies one value to every
row, so twenty seeded orders share one supplier — adequate for a smoke test, thin for
anything relational. A fixture cannot carry a per-row value either: the key is refused as
an unknown create-command field. Both measured:

```
2 rows seeded, distinct supplier names = {'Shared'}
fixtures=({"supplier": {...}},) → CoreException: Fixture row 0 for 'orders' has field(s) …
```

Neither is a defect in what shipped; both are the next phase, and the RFC's §2 reach claim
depends on the second more than on anything already built.

**A-9 · The marker's "real backends are unchanged" was untested.** The differential proved
it for the resolved form; the marker declares strictly less and was easier to believe, which
is why it went unchecked. Now covered against a real view
(`test_a_marked_field_is_read_from_the_view_unchanged`).

## Review round 1 — 2026-09-11

Six findings, all reproduced before any fix, and all valid.

**R-1 · `read_conformity="lenient"` made a spec unconstructible.** A derived field with a
static default (`total: int = 0`) was auto-derived into the lenient set and then refused
for overlapping with its own declaration. Derived names are now excluded from the
auto-derivation, and the overlap check compares against the *explicit* lenient set only.

**R-2 · A projection excluding a marked field was refused for it.** `_hydrate` validated
every marked field regardless of what the caller asked for, so `project_many(["id"])` on a
spec with an unsupplied marked field failed a read that could not have exposed it. The
projection is now passed through and only requested top-level names are required.

**R-3 · `create` drains domain events before it returns**, so a handler reading the new
aggregate ran before the seeder wrote its derived values and saw a required marked field
as missing. Closed by staging the values around the create, keyed by `(spec name, pk)`;
the stored row wins where it has a value, because staging covers a window rather than
overriding what was persisted. That precedence was wrong in the first cut and its own test
caught it.

**R-4 · A dynamically-namespaced source resolved to the fallback namespace, silently.**
`_namespace_for` answers synchronously and cannot evaluate a resolver, so the join read
whatever sat in the default namespace. Refused at wiring for the same reason as the
tenancy mismatch: both available outcomes are wrong and the failure presents as missing
data.

**R-5 · A documented example could not run.** The `SpecSeed` snippet used a read-only
spec, which `SpecSeed` refuses — seeding goes through the create command. The corpus gate
resolves imports, not runtime validity, so nothing caught it. Fixed in all three places
the example appears.

**R-6 · A resolved join reads the source's stored row and cannot decrypt it**, so a
sealed source field arrives as ciphertext. Not fixable where it was found: the deps
factory sees route configs, never the source spec, so it cannot know what the source
encrypts. Recorded on the declaration as a limit to know, with "mark it instead of
resolving it" as the answer.

**Sweep: 7 mutations, 6 killed, 1 proven equivalent.** The survivor swapped the explicit
lenient set for the resolved one in the overlap check — a no-op once R-1's exclusion
guarantees the auto-derived set holds no derived name, proven rather than assumed:

```
names & explicit = []   names & resolved = []   equivalent: True
```

## Review round 2 — 2026-09-11

No new threads and no new reviews; every round-1 thread resolved. The one signal was
codecov reporting patch coverage at 98.1% with four uncovered lines, and one of the four
was mine: the refusal of a field declared both derived and `write_omit`. The guard was
written in the first commit and nothing asserted it — a promise with no test, which the
per-module coverage runs missed because they measured `_derived.py` and `derived_read.py`
and never `specs.py`. Covered now.

The other three blame to commits that predate this branch (`9502d938a`, `96f723c5a`,
`baf38ab7c`) and are left alone.

The lesson is about the measurement, not the guard: coverage scoped to the modules a
change *adds* misses the lines it adds to modules that already existed.
