# T-0048 · Derived read fields

Executing RFC 0048 against branch `feat/derived-read-fields`.

**Drift count: 0.**

Where building this disagreed with the design for it, written at the moment it
happened. Nothing here is revised afterwards to agree with what was later
settled, and nothing here has been folded back into the RFC's own text. The rows
proposed below are put forward for the author to accept or refuse; execution does
not write them into a decision table itself.

| Class | Test | Meaning |
|---|---|---|
| `discovery` | Could not have been known before code existed | Healthy — the spec was right to be silent |
| `spec-gap` | Could have been known; the spec was silent or at the wrong altitude | The design process missed something |
| `drift` | The spec covered it and it was built otherwise anyway | **A defect** |
| `irreducible` | No amount of design settles it | Stop and spike |

## Two gaps the plan found before writing anything

```divergence
decision: UNLISTED
grade: UNLISTED
class: spec-gap
at: 2026-09-10T19:20:00Z
attempt: 1
claim: the mock has nine decode sites, so synthesis placed at any single read method leaves the feature silently absent from the others; the RFC names no seam
evidence: `grep -c "_to_read(\|_to_read_or_projection(" src/forze_mock/adapters/document.py` → 11
action: decided
proposal: LOCKED — synthesis is applied at one hydration point that every decode routes through, never per read method. A derived field that resolves under `get` and vanishes under cursor paging is worse than one that is refused, because only the second is discoverable.
```

```divergence
decision: UNLISTED
grade: UNLISTED
class: spec-gap
at: 2026-09-10T19:24:00Z
attempt: 1
claim: a spec carrying both encryption and a derived field is refused by the existing encryption reconciliation, which subtracts only the lenient set from the stored field names
evidence: src/forze/application/contracts/document/specs.py:226-229
action: decided
proposal: ASSUMED — a derived field is not stored, so it is subtracted from the encryption reconciliation exactly as a lenient field is. It cannot be sealed at rest for the same reason it cannot be filtered: there is no column.
```

## Settling the OPEN rows

```divergence
decision: D-7
grade: OPEN
kind: resolved
at: 2026-09-10T19:52:00Z
attempt: 1
claim: the mock reads a source row through the reading adapter's own store accessor, so a derived read observes the same transaction view the reading document does; the source's namespace and tenant-awareness are resolved by the deps factory from the module's route table, not by the adapter
evidence: src/forze_mock/adapters/document.py:198-220
action: decided
proposal: LOCKED — resolution is a wiring fact and belongs in the factory. Reading the source outside the MVCC overlay would let a snapshot transaction observe a sibling write it must not see, which inverts what the overlay exists for.
```

```divergence
decision: D-7
grade: OPEN
kind: resolved
at: 2026-09-10T19:54:00Z
attempt: 1
claim: a tenant-aware source read from a non-tenant-aware reader has no bound tenant to partition the source namespace with, so the join reaches the unpartitioned namespace — finding nothing, or another tenant's row
evidence: src/forze_mock/adapters/_derived.py:118-131
action: decided
proposal: LOCKED — the pairing is refused at factory time (`mock.document.derived_tenant_mismatch`) rather than resolved. Both available resolutions are wrong, and the failure would present as missing data rather than as a cross-tenant read.
```

```divergence
decision: UNLISTED
grade: UNLISTED
class: discovery
at: 2026-09-10T20:02:00Z
attempt: 1
claim: the Postgres startup schema validator needs no change; §5.2 asserted one. Write validation reads the DOMAIN model, and a derived field is declared against the read model only, so write validation never sees it. Read validation requires the column on the read relation, which is what the design wants.
evidence: src/forze_postgres/execution/lifecycle/document_schema.py:88-93
action: decided
proposal: ASSUMED — the validator is untouched. What the RFC took for a needed change is instead a guardrail on the spec: a derived name that is also a stored domain field is refused, because otherwise the boot fails with a message about the write relation rather than about this declaration.
```
