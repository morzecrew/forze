## Readiness: the gate does not trip

The one thing worth stating before any code: an RFC written by the executor is weaker
evidence than one written by an author with separate context, because the grades cannot
disagree with the implementation that is about to be written. What protects against that
here is that every row's rationale is a fact about the existing tree, cited in §3 and
verifiable without reading the new code.

**Findings — four, all fixed.**

1. **The locked security property was not tested** (above). A 400 body now carries a
   `debug_access_token` and an `internal_trace` object alongside its error code, and the
   test asserts both are absent from `details`. The raw-body mutation fails it.
2. **A colon in a Basic user-id was accepted.** RFC 7617 splits the decoded pair at the
   first colon, so `username="a:b"` with password `"c"` presents user `a` with password
   `b:c` — a credential that reads correctly in the config and is not the one the
   counterparty receives, failing as an authentication error nobody can explain from the
   wiring. Refused at construction now, beside the both-halves check.
3. **`header_name` was silently ignored for `basic`.** The header was hardcoded to
   `Authorization` while the config happily accepted a different name — a field the config
   takes and drops. It is honoured, like the `api_key` and `header` kinds.
4. **The declaring path's own context was unasserted.** Because a declaring operation
   raises from the adapter rather than from the client, its `details` come from a different
   place; nothing checked that the operation, service, method and URL still travel, so a
   regression there would degrade every log for exactly the operations that declared the
   most. Asserted now.

**What the sweep established.** Ignoring the encoding, accepting a nested value, rendering
a boolean as `True`, sending `None` as empty, leaving `raise_for_status` on, re-raising on a
malformed error body, dropping the half-Basic refusal, reverting the optional-secret
converter, dropping `data=` in the routed wrapper, and composing the Basic blob without its
colon each fail between one and three tests. The two that would silently corrupt — the
boolean spelling and the converter — are pinned by name.

**Residue.**

- *`body_encoding="form"` on a `GET` is inert rather than refused*, per the field's own
  docstring. A caller who sets it expecting query encoding gets JSON-shaped query params,
  which is what they would have got anyway.
- *`query_from` combined with a form body is untested.* It falls out of the existing split
  (query keys leave the mapping before the body is built) and no consumer combines them.
- *The client's arg enrichment still carries a request body into `details` for
  non-declaring operations.* That predates this branch, and the scrubber redacts the
  secret-shaped keys — asserted for a form-encoded `client_secret`, which is the case RFC
  0024 depends on.

### Round 2 and 3 — 2026-09-13

Round 2 re-sabotaged the four fixed paths against the committed batch: the raw-body
passthrough now fails two tests instead of none, and dropping the colon refusal, the
`header_name` honouring or the adapter's own details each fail one. Round 3 ran the touched
suites under random ordering (1538 passed) and probed one interaction the RFC does not
mention — a declared error body larger than `max_response_bytes`. The cap wins, the
exception names it, and no declared detail is attached, which is the right order: a
response the client refused to read cannot be described by a model.

No new defect in either round.

**Convergence.** Four findings, then none, then none. The one that mattered was invisible
to eleven mutations and eighty-three passing tests — an implemented security property with
no assertion behind it — and it was found by mutating *toward* the forbidden behaviour
rather than away from the intended one.

**Residue, added.**

- *`forze_mock`'s HTTP registry does not synthesize a declared error body.* An app
  scripting a provider rejection through it raises the `CoreException` itself, including
  the `response_error` detail if its code reads one. The kit that RFC 0024 ships will mock
  at its own level rather than at the transport's, so nothing needs the mock to grow this;
  said here because the asymmetry is otherwise discovered by a confused test author.
