## Self-audit — 2026-09-14

**Scope.** The whole branch: 4 commits, the rewritten capability index (83 → 96 lines), the
two exemption groups deleted from `pyproject.toml`, a new bar in `docs_floors.py` (+95
lines) and its test file (15 tests). Four sabotage rounds, 23 mutations.

**Finding 1 — the gate could not see attribution (round 1, fixed).** Of six mutations
against the page, five were caught (a key dropped from a row, a typo'd key, a blanked key
cell, a broken link, a re-added exemption group). The survivor was the one that matters:
swapping two rows' keys left every symbol mentioned, so the symbol bar stayed green while
the index named the wrong key for two capabilities. An index of 75 keys that a reader
trusts is worse wrong than absent. Fixed by `check_dep_key_attribution`, which reads the
key↔accessor mapping out of the accessors' own source and requires a row naming a
resolvable key to show the accessor that resolves it.

**It found two real errors in the page on its first run**, which is the argument for it:
dynamic read has a `ctx.dynamic_read.query(spec)` accessor and the index claimed it had
none, and the transactions row named only the ambient `ctx.tx_ctx.scope(route)` while the
key it listed is resolved by `ctx.transaction(route)`. Both were mine, and both had
survived a read-through.

**Finding 2 — two shapes the new bar accepted (round 2, fixed).** Reading keys from the
whole row rather than its last column survived, and so did letting a row that shows no
accessor off the hook. The second is the dangerous one: *by dep key* is how the durable and
queue rows are written, so it would have become a way to silence the bar on a capability
that does have an accessor. Both pinned by tests.

**Finding 3 — the bar was not pinned as *running* (round 3, fixed).** Deleting it from
`main`'s violation sum, and deleting the `dep_key_index` line that arms it, both left the
suite green — the "built the mechanism, not the gate" failure this repository keeps
finding, in the gate itself. Two tests now pin the wiring and the config line, and a third
pins that only table rows attribute (matching every line mentioning a key was also
invisible).

**Two survivors, both ill-posed, neither a test gap.** Collapsing a key's owner set to a
single accessor changes nothing: no key is referenced by two accessor classes today
(verified — 57 mapped keys, zero with two owners), so the mutation is a no-op against the
live tree and the set shape is defence for a future that has not arrived. Leaving the
capability label's markdown link in the violation message changes only the message.

**Residue.**

- *Attribution is verifiable for 57 of 92 dep keys.* The rest — the durable family, queue,
  pub/sub, the crypto internals, the identity lifecycle ports — have no `ctx` accessor, so
  nothing derives what row they belong to. Their placement rests on review, and the bar
  stays silent rather than guessing.
- *"Documented" is weaker than it reads for short aliases.* The symbol bar accepts a
  substring match on a dep key's wire name, so `CacheDepKey` counts as documented because
  the word `cache` appears somewhere in the corpus. Thirteen keys are named nowhere by
  symbol; twelve are the identity group P2 owns, and `PasswordResetDepKey` passes on its
  alias alone. Worth P3's attention when it extends this gate — it is the gate's bar, not
  this phase's.
- *No rendering check.* The tables are shape-verified (52 rows, every one four cells) but
  nothing in CI renders the page.

**Convergence.** Round 1 found one defect, round 2 two, round 3 one plus two ill-posed,
round 4 found nothing new. Every real finding is fixed on the branch.
