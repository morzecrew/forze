`feat/anthropic-messages-dialect`: a second generation dialect over Anthropic's native
`/v1/messages`, on the same kernel client, config and adapter. No SDK, no client, no extra.

Grades are copied from the RFC's §8 table as it stood at `a796ece4d`, where P2 was re-scoped
from a native provider client to this dialect (row 22).

`max_tokens` is required and the constraint is sent as `output_config.format` — so that row is
honored rather than departed from; the evidence is in the first entry below, which needed the
same lookup. The one departure is from row 4, whose "iff `openai_chat`" no longer describes a
plane with two generation dialects.

## Audit — 2026-09-17, four commits, 12 files, +1554/−412

Scope: the whole branch against `main` (`audit_scope.py scope --base main`) — the extraction,
the dialect, the wiring, the battery, the docs. Re-read §6's P2 exit criteria and rows 22–25
first. Suite: 300 passed in `tests/unit/test_forze_inference`, 427 with the examples.

**Finding 1 — two claims the code does not hold.** The module docstring listed `$ref` among
the features the chat dialect refuses; strict mode accepts it, and the real differences are
the string formats, the defaulted property and the non-empty list. The node rule's docstring
counted three checks against four in the body. Both fixed; the docs table was right already,
which is how the disagreement surfaced.

**Finding 2 — `__all__` on two modules that have no siblings with one.** Added with the
dialect and copied into `openai_chat`, where nothing had declared one. Removed: a list kept
in step with the imports by hand is a list that goes stale.

**Finding 3 — two sabotages survived, both the same defect in the tests.** An empty text
block accepted by the dialect (`M9`) and a JSON array decoded as a record (`M10`) both left
the suite green, because each test asserted only `inference_output_mismatch` — a code the
JSON decode and the output codec also raise. The code was right; the assertion could not
tell which guard produced it. Worse, in **text mode there is no second guard**: under `M9` a
message whose only block was empty would have been a successful prediction of empty prose,
and no test covered that at all. Both assertions now name what only this dialect says, and
text mode has its own case. Re-run: killed.

**Finding 4 — four branches with no test, and one of them was load-bearing.** Patch coverage
(97.03%, 294/303) named them after the sabotage sweep came back clean, which is the pass-9
point exactly: the sweep measured what I thought to break. The `allOf`-carrying-a-`$ref`
rule, a content block that is not an object, decoding a response for more than one instance
— and `schema.py:156`, the visited set in the reference walk. That last one is not an
efficiency guard: a model reaching a cycle it is **not part of** (`_Outer` → `_Ping` ↔
`_Pong`) is walked from a name the cycle never returns to, so without the set the traversal
follows it forever. Proved by removing it: the run does not finish. Patch coverage after:
99.7%, and 16 of 16 mutations killed.

**Residue — what I would still distrust.**

- `_nested_fields`' own `except ValueError` (`generation.py:101-103`) is unreachable, and
  inherited from P1: `Formatter().parse` raises on the whole template first for every
  unparseable spec I could construct (`{x:{}`, `{x:{y}`, `{x:}}`). Left as written — its
  comment says exactly this — and it is the only uncovered line on the branch.
- `prefixItems` is not walked. Nothing reaches it today: a fixed-length tuple carries
  `minItems`/`maxItems`, which both dialects refuse, so the parent is refused before the
  members are read. A future schema with `prefixItems` and no bounds would walk unchecked.
- The provider's temperature ceiling (1, against OpenAI's 2) is still not checked at wiring
  — the config's refusal message says so in as many words, and this branch did not change
  that stance.
- `usage.input_tokens` excludes cache reads, which Anthropic reports in separate fields. The
  dialect never sends `cache_control`, so nothing is cached and nothing is missed; a route
  that gains prompt caching would under-report.
- Nothing here has run against a live endpoint. Every assertion is against
  `httpx.MockTransport` shaped from the published field tables and the provider's own
  generated SDK types.

## Audit round 3 — the round-2 fix, and what the branch carried by accident

The new refusals are the fixes this round audits, and they are the kind that can refuse a
working route. Walked every node shape the walk visits, against what Pydantic actually
emits: a `$ref` property, an optional field's `anyOf` with its `null` member, a `Literal`
whose members have no `type` of their own, an array's `items`, a `$defs` entry, and the root.
`type`, `$ref`, `anyOf`, `enum` and `const` are the five spellings that make a node
constrainable, and each of those shapes carries one. The whole unit suite agrees: 14408
passed, 7 skipped — ten more than before the round, none of them elsewhere.

**Finding 5 — an unrelated file rode along.** `ruff format` over the whole test directory
reflowed an over-long assertion in `test_routed_inference_clients.py`, which this branch does
not touch. Restored from `main`. The rule it broke is already written down: format the files
you edited, never a directory.

Two things this branch deliberately does not carry, so they are not silent omissions:

- No streaming leg for the new dialect. `predict_stream` is the adapter's, not the dialect's,
  and the chat battery already drives it over the same fan-out with `instances_per_request`
  of 1; a per-dialect copy would assert the adapter twice and the dialect not at all.
- No recipe. §6's P2 exit does not ask for one, and the shipped recipe's route is the chat
  dialect on purpose — its capability mirror is identical either way, since both dialects
  score one instance per request.

**Residue after three rounds.** Unchanged from round 1, minus the two it fixed: the
unreachable `except ValueError` in `_nested_fields` (the only uncovered line on the branch),
`prefixItems` unwalked and unreachable today, the provider's temperature ceiling unchecked
at wiring, cache-read tokens outside `usage.input_tokens` on a route that never caches, and
a boolean-valued property schema (legal JSON Schema, never emitted by Pydantic) which the
walk skips before the untyped check can see it. Nothing here has met a live endpoint.

**Drift count: 0.**
