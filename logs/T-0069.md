# T-0069 — Session revocation fast path, phase 1

Executing phase 1 of [RFC 0069](../rfcs/0069-session-revocation-fast-path.md) on
`fix/authn-atomic-revocation`. The revocation paths commit atomically. Login's and refresh's
eligibility checks share one transaction with their session inserts, under a locking read of
the policy principal. The mock's `deactivate` revokes sessions.

The plan turned up three load-bearing questions the RFC does not settle (entries 1, 3 and 4).
They went to the author before any code was written, and the author accepted every proposal
below on 2026-10-13.

```divergence

class: spec-gap

claim: in a transaction, refresh-token reuse detection undoes itself, because the adapter revokes the family and then raises, and the raise rolls the revocation back
evidence: src/forze_identity/authn/adapters/token_lifecycle.py:201-212 — `revoke_chain_of_tokens(...)` followed by `raise exc.authentication("Invalid refresh token")`; the mock does the same under its identity snapshot, which a rollback restores
action: decided
proposal: LOCKED — on reuse the lifecycle raises `RefreshTokenReuseError`, an authentication error with the uniform summary and code, carrying the principal and the family. The refresh handler, once its transaction has rolled back, revokes the family in a transaction of its own and re-raises. `TokenLifecyclePort` gains `revoke_chain_of_tokens` so the handler can. A caller outside any transaction keeps today's behaviour, since the adapter still revokes in-line.
```
