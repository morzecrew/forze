```divergence
decision: unlisted
grade: UNLISTED
class: spec-gap
at: 2026-09-10T05:14:00Z
attempt: 1
claim: §4 requires staged inputs and collected outputs and never says how they cross a container boundary; the process tier's answer — a real host directory the child works in — is available here as a bind mount and carries a host path into code this tier exists to distrust
evidence: `d=$(mktemp -d); docker run --rm -v $d:/w python:3.12-slim sh -c 'echo hi > /w/f'; stat -c '%U:%G %a' $d/f` printed `root:root 644`
action: decided
proposal: ASSUMED — files cross as tar through `PUT`/`GET /containers/{id}/archive`, not as a bind mount. Deliberately the opposite trade from the process tier: a bind mount is less code and requires the daemon on this host, hands the child a writable path on it, and writes back as whatever uid the container ran as — root by default, and something else again under a user namespace, so the worker cannot reliably read its own outputs back. The archive endpoints cost a stream each way and work against a remote or rootless daemon, which is the topology an app that actually isolates untrusted code is most likely to have.
```

claim: the request's own process is PID 1 of the container's pid namespace, where the kernel discards signals whose disposition is default — so the CPU ceiling's SIGXCPU never arrives, the run survives to the hard limit, and what comes back is a bare SIGKILL indistinguishable from the adapter's own kill
