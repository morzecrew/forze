# T-0059 — Non-disclosing denials

Executing [RFC 0059](../rfcs/0059-non-disclosing-denials.md) P1–P3 on
`feat/non-disclosing-denials`.

## Plan

- `base/exceptions/model.py`: `CoreException.resource_type` — a typed optional field, threaded
  through `of` and the per-kind factories (D-8).
- `base/exceptions/egress.py`: `DenialPosture(mode, resource_types)` and a process-wide
  `configure_denial_posture` / `current_denial_posture`; default `standard` (D-4).
- `base/exceptions/envelope.py`: `error_envelope` returns one canonical not-found envelope for an
  `AUTHORIZATION` or `NOT_FOUND` exception whose `resource_type` the posture covers (D-1, D-2, D-3).
- `execution/runtime.py` + `assemble.py`: `denial_posture=` on the runtime, bound for the scope.
- `hooks/authz/plans.py`: a denial raised with an `AuthzResource` carries its `resource_type`;
  one without a resource stays untagged and renders 403 (D-7).
- Document adapters (core and mock): a `NOT_FOUND` raised by any public coroutine method carries
  the spec name as its `resource_type` — tagged at one base class, so an override in a subclass is
  tagged too (D-6).
- `contracts/document`: `OwnedBy(field, value)` and `owned_by=` on `get` / `get_many`; core adapter
  and mock (D-5, D-8).
- Trace + DST: the operation's error terminal records a digest of the rendered envelope; a
  `denial_bodies_identical` history invariant (P3).
- Batteries: byte equality across FastAPI and Socket.IO for four reasons; posture off keeps 403 and
  its context; resource-less denial stays 403; `owned_by` across mock, Postgres, Mongo, plus the
  core adapter's cache leg; the DST invariant with a sabotage leg.
- Docs: errors page section, `owned_by` in the document-port reference; changelog.

Decisions the spec does not settle were put to the author before code (four answers below); the
rest are decided here.
