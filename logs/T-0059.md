# T-0059 — Non-disclosing denials

Executing [RFC 0059](../rfcs/0059-non-disclosing-denials.md) P1–P3 on
`feat/non-disclosing-denials`.

## Plan

- `base/exceptions/model.py`: `CoreException.resource_type` — a typed optional field, threaded
  through `of` and the per-kind factories (D-8).
- `base/exceptions/egress.py`: `DenialPosture(mode, resource_types)` and a process-wide
  `configure_denial_posture` / `current_denial_posture`; default `standard` (D-4).
- `base/exceptions/envelope.py`: `error_envelope` returns one canonical not-found envelope for an
  `AUTHORIZATION` or `NOT_FOUND` exception whose `resource_type` the posture covers (D-1, D-2, D-3).
- `execution/runtime.py` + `assemble.py`: `denial_posture=` on the runtime, bound for the scope.
- `hooks/authz/plans.py`: a denial raised with an `AuthzResource` carries its `resource_type`;
  one without a resource stays untagged and renders 403 (D-7).
- Document adapters (core and mock): a `NOT_FOUND` raised by any public coroutine method carries
  the spec name as its `resource_type` — tagged at one base class, so an override in a subclass is
  tagged too (D-6).
- `contracts/document`: `OwnedBy(field, value)` and `owned_by=` on `get` / `get_many`; core adapter
  and mock (D-5, D-8).
- Trace + DST: the operation's error terminal records a digest of the rendered envelope; a
  `denial_bodies_identical` history invariant (P3).
- Batteries: byte equality across FastAPI and Socket.IO for four reasons; posture off keeps 403 and
  its context; resource-less denial stays 403; `owned_by` across mock, Postgres, Mongo, plus the
  core adapter's cache leg; the DST invariant with a sabotage leg.
- Docs: errors page section, `owned_by` in the document-port reference; changelog.

Decisions the spec does not settle were put to the author before code (four answers below); the
rest are decided here.

## Self-audit — 2026-09-26

Scope: whole branch, 4 commits, 33 files (+1.7k lines: 467 source, 1037 test, 203 docs).

1. **Fixed — a posture could protect nothing without a word** (`91be3836b`).
   `DenialPosture(resource_types="notes")` became the set of its letters, and a misspelled
   `mode` read as `standard`; either left every covered type disclosing. Both are refused now,
   each with its own leg.
2. **Fixed — a first-wins tag was unpinned.** Sabotaging the wrapper to overwrite an existing
   `resource_type` survived the whole suite. A not-found that already names its type now keeps
   it by test, beside a structural test that every public coroutine on every document adapter
   class is tagged and a leg that only not-founds are.
3. **Fixed — a docstring over-claimed.** `get` said a foreign row is "neither read nor locked";
   a read through the cache fetches by pk and checks after, so it is read. Reworded.
4. **Fixed — duplicated cache wiring** in the three integration legs, now `mock_read_cache`.

Checks run: sabotage of 23 mutants across the envelope, posture, hook, tagging, both adapters'
owned reads, the trace digest, the projection, the invariant and the runtime binding — 22
killed on the first sweep by an assertion (each kill's failing test read, not only counted),
the one survivor (item 2) killed after its test. Patch coverage over the added source lines:
100% (unit suites plus the Postgres, Mongo and Firestore legs). `just quality`: all gates.

Residue: an owner field that is sealed with non-deterministic encryption cannot be filtered, so
the database path refuses where the cache path would compare decrypted values — loud, not
leaky, and untested. Timing is out of scope by design. `list`/`find_many` take no `owned_by`
(RFC §10 leaves it open).
