# T-0064 — Principal-scoped idempotency claims

Executing [RFC 0064](../rfcs/0064-principal-scoped-idempotency-claims.md) P1–P3 on
`feat/principal-scoped-idempotency`.

## Plan

- `contracts/idempotency/ownership.py`: `ClaimPrincipalMixin` beside `ClaimOwnerMixin` — a
  `principal_provider` wired like the tenant, and the one function that turns a caller's key
  into the stored one.
- The four stores (mock, Postgres, Mongo, Redis) scope the key right after their existing
  `if not key` guard in `begin` / `commit` / `fail`, so every statement below sees the scoped
  key and none can forget it.
- The four factories wire `principal_provider=ctx.inv_ctx.get_authn`.
- `integrations/idempotency/encryption.py`: the AAD's record id is the scoped key; the hook
  passes the provider.
- Batteries: the disclosure leg first, then the RFC §6 legs, per store; a DST leg with two
  principals and one key.
- P3: a `check_wiring` warning for a store that cannot scope, the docs sentence, the changelog.
