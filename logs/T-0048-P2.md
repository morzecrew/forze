## Step 0, before any source change: what running it actually found

Three things, in the order a reader would hit them.

**F-1 · An invariant cannot run over a view-backed aggregate at all.** A workload that
creates a row and reads it back fails on the read, because a marked derived field is
refused on the create command and so nothing supplies it. Confirms the hand-off residue
rather than discovering it:

```
strategy=OP_CASE count=4 act_count=4 concurrency=2 seeds=range(2)
handler: create(OrderCreate(...)) then get(id)
→ Violation(invariant='operation_succeeds',
            message="operation 'place_order' did not succeed (outcome=failed)",
            fields={'outcome': 'failed', 'error': 'CoreException'})
```

**F-2 · The seeder cannot seed under simulation.** `SpecSeed.derived` was the documented
answer for a marked field, and it is unreachable from a `Simulation.setup` hook: the
seeder narrows the port to `MockDocumentAdapter` with an `isinstance`, and DST hands it a
`TracingPortProxy` wrapping that adapter.

```
setup=apply_seed(ctx, SeedPlan(specs=(SpecSeed(spec=ORDERS, count=3, derived=DERIVED),)))
→ CoreException(core.configuration): Seeding derived values for 'orders' needs the mock
  document adapter; got TracingPortProxy
```

This is a defect in what P1a shipped, not a gap in the design — the `isinstance` arrived
in review round 6 to stop a private method being reached through a public protocol type,
and it narrowed to the concrete adapter rather than to the adapter *behind the proxies*.

**F-3 · The default DST posture reports none of it.** `no_unexpected_error()` — the
zero-instrumentation net, and the only invariant an uninstrumented run has — classifies a
`CoreException` as an expected domain outcome, by design. A configuration refusal is a
`CoreException`, so a run in which every single operation fails on wiring is green unless
the author also declares `operation_succeeds`. Recorded, not fixed: the classification is
every plane's, and narrowing it is not this RFC's to do.
