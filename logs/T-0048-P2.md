## Step 0, before any source change: what running it actually found

Three things, in the order a reader would hit them.

**F-1 · An invariant cannot run over a view-backed aggregate at all.** A workload that
creates a row and reads it back fails on the read, because a marked derived field is
refused on the create command and so nothing supplies it. Confirms the hand-off residue
rather than discovering it:

```
strategy=OP_CASE count=4 act_count=4 concurrency=2 seeds=range(2)
handler: create(OrderCreate(...)) then get(id)
→ Violation(invariant='operation_succeeds',
            message="operation 'place_order' did not succeed (outcome=failed)",
            fields={'outcome': 'failed', 'error': 'CoreException'})
```

**F-2 · The seeder cannot seed under simulation.** `SpecSeed.derived` was the documented
answer for a marked field, and it is unreachable from a `Simulation.setup` hook: the
seeder narrows the port to `MockDocumentAdapter` with an `isinstance`, and DST hands it a
`TracingPortProxy` wrapping that adapter.

```
setup=apply_seed(ctx, SeedPlan(specs=(SpecSeed(spec=ORDERS, count=3, derived=DERIVED),)))
→ CoreException(core.configuration): Seeding derived values for 'orders' needs the mock
  document adapter; got TracingPortProxy
```

This is a defect in what P1a shipped, not a gap in the design — the `isinstance` arrived
in review round 6 to stop a private method being reached through a public protocol type,
and it narrowed to the concrete adapter rather than to the adapter *behind the proxies*.

**F-3 · The default DST posture reports none of it.** `no_unexpected_error()` — the
zero-instrumentation net, and the only invariant an uninstrumented run has — classifies a
`CoreException` as an expected domain outcome, by design. A configuration refusal is a
`CoreException`, so a run in which every single operation fails on wiring is green unless
the author also declares `operation_succeeds`. Recorded, not fixed: the classification is
every plane's, and narrowing it is not this RFC's to do.

## Self-audit — 2026-09-11

Scope: the whole branch, 1 commit / 12 files / +701-19, against merge base `9f8c538e3`.
Eight sabotages, each proven to change behaviour before its verdict was read; one survived
and cost a test.

**A-1 · A test that asserted nothing.** `test_an_undeclared_key_is_ignored` claimed the
source's keys are scoped to the declared derived names. Deleting the scoping left it green:
the key it supplied was one pydantic drops as an extra field, with or without the filter.
The scoping's real subject is a field *absent from the stored row that has a default* — a
read-model default or a lenient field, which a sloppy source would fill silently. Rewritten
against that (`test_it_cannot_fill_a_field_the_spec_did_not_declare_derived`), and the
sabotage now kills it.

**A-2 · Precedence, wrong on the first cut.** The source was merged before staging, so a
stand-in for every row outranked a value staged for one row. Caught by the test written
alongside it, and the fix is three explicit ranks in one place: source, then staging, then
the stored row. The same ordering trap as P1's `{**doc, **staged}` — worth naming, since it
has now appeared twice in one feature.

**A-3 · A simulation that did not replay, and the reason was in the test.** The
determinism case failed until the handler minted its ids through the framework's `uuid4`
rather than the stdlib's: a simulation binds a seeded entropy source per run, and a handler
drawing outside it makes two runs of one seed disagree. Not a framework defect — but it is
the trap a source author hits first, so the docs now say to keep a source a function of the
row.

**A-4 · The projection order was right and unpinned.** `_hydrate` runs on the whole stored
row and `_project` after it, so a source can read a join key the caller did not ask for.
Nothing asserted that, and the reverse order would have broken every such source silently
and only on the projection path. Now pinned, and the sabotage that reverses it kills two
tests.

## Residue at hand-off — 2026-09-11

**A configuration refusal reads as an expected outcome under DST.** F-3 above, restated as
residue because it outlives this phase: `no_unexpected_error()` is the whole oracle an
uninstrumented run has, and it passes on `CoreException`. Every wiring refusal in the
framework is one. So a simulation over a misconfigured spec is green while nothing works,
and the only reason this phase noticed is that `operation_succeeds` was declared as well.
Narrowing the classification is every plane's question, not this RFC's.

**Decision row 6 is untouched and now looks different.** A derived field is excluded from
the filter, sort and aggregate sets because the mock has no value for it on the rows it
would have to scan. With a registered source it has one for every row, so the technical
reason the exclusion cites is weaker than it was — the policy reason (a fixture value is
not the view's answer, and filtering on it would return rows production would not) is what
is left holding it. Still the author's call, unchanged here.

**A source is called once per row per read.** No caching: a scan of a thousand rows calls
it a thousand times. Mock-only and deliberate — a cache would have to be invalidated
against a store the source is free to read — but an expensive source will be felt in a
large simulation.
