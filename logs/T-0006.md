`feat/openai-chat-protocol`: one more dialect on the shipped inference-HTTP plane, prompt as
route config, no new package and no provider client.

Grades are copied from the RFC's §8 table as it stood at `7f05c10d5`. Three of the entries below

derived from and *where* a refusal maps to, and are honored as written — what they do not settle is
the strictness of the constraint sent and the response field a refusal is read from. Close-outs for

## Audit — 2026-09-15, one commit (`898862441`), 15 files, +2234/−22

Self-audit over the whole branch: 10 passes, sabotage before coverage. Findings and their
fixes are below; the two entries that follow are decisions the audit found unlogged.

**Findings, ranked.**

1. **The provider's refusal wording reached the caller** (fixed). A content refusal embedded
   the provider's explanation in the error summary, which for every kind below 500 renders
   verbatim to whoever called the API. That text quotes the prompt back, and the prompt is
   built from the caller's own input on a plane the kernel client already treats as
   PII-dense — it withholds upstream bodies from errors *and* from logs for exactly this
   reason. The wording is now withheld and the test asserts its absence.
2. **A failed fan-out lost the tokens it had spent** (fixed). Usage attributes were set
   after the loop, so a batch that failed on its third request reported nothing — losing the
   count precisely when it matters. The write moved into a `finally`; it cannot outrank the
   outcome, since `set_attribute` does not raise for the ints it collects.
3. **The budget test proved nothing about the per-call check** (fixed). It asserted that a
   zero budget sends no request, which a single check before the fan-out passes just as well
   — and the first sabotage of that check was itself defective: it deleted the call rather
   than moving it, so "killed" said nothing. A second test now spends the budget inside the
   first request and asserts the remaining two are never sent.
4. **A dialect declaring `instances_per_request=0` crashed inside the stdlib** (fixed).
   `itertools.batched` raises a bare `ValueError` below 1; the sibling per-call batch hint
   already refuses that value by name, and the widened interface did not. Refused now, with
   the same shape.
5. **The recipe's docstring was wrong about the derived driver** (fixed). It claimed
   `forze dst run` cannot drive the workload — copied from the sibling recipe, where it is
   true. Here a triage function answers any string, and the derived run reports `raced 2/2`
   and `at risk 3–3 of 3 runs per invariant`. The docstring now says so and gives the
   command; the scenario's actual purpose (recognisable tickets) is stated instead.
6. **Duplication** (fixed): one recording handler replaced five identical closures in the
   protocol battery, and one `_scope` helper replaced four copies of the runtime/deps setup
   in the recipe battery.

**Sabotage.** 13 mutations, 13 killed, plus the two the audit's own fixes added. The one
survivor-shaped result was finding 3 above, which was a defective mutation rather than a
test gap: re-run as a move rather than a deletion, it is killed by the new test.

**Residue — what I would still distrust.** The strict-mode keyword list is a judgement about
a provider's behaviour taken from its documentation, not from its endpoint: a keyword it
quietly accepts is refused here, and a keyword it started rejecting is not. The nesting-depth
and property-count ceilings are not checked at all (named in the constant's docstring); they
surface as a rejected request. Nothing here has run against a live provider — every assertion
is against `httpx.MockTransport` shaped from the two published field tables.

## Audit round 2 — coverage, and what sabotage could not see

Patch coverage over the added lines: **98.23% (222/226)** on the first measurement, with all
four gaps in the new dialect and none in the adapter, the config or the two existing
dialects. Sabotage had passed everything at that point, which is exactly the pair the rule
warns about: a clean sweep next to an uncovered branch means the branch is unproven, not
fine.

Two of the four were real gaps rather than unreachable code:

1. **A completion with no content at all** — not a refusal, not prose. The refusal tests
   reach the same response shape but stop at the refusal branch, so the "model answered
   nothing" path only ever ran when something else was also wrong. Now tested for both
   `null` and `""`, asserting the reason is named in the message.
2. **A choice that is not an object** (`{"choices": ["nope"]}`). The parametrized case
   covered a non-list `choices` but not a list of non-objects.

The other two are the dialect's own invariants — encoding two instances, decoding for two —
reachable only by a caller using the protocol directly rather than through the adapter, and
`internal` for that reason. Tested directly rather than deleted: the interface is public.

Patch coverage after: **100% (160/160)** of the dialect's added lines.

**Two process findings, recorded because both are the kind that repeats.**

- The sabotage harness restores each mutation with `git checkout --`, and the audit's own
  fixes were not yet committed — so the first re-run silently reverted them, and one
  mutation then read as "killed" while being killed by collateral damage in two unrelated
  tests. Every fix batch is a new baseline *before* the next sweep, not after it.
- One mutation turned `finally:` into `else:` in a `try` with no `except`, which is a

## Review round 1 — PR #439, thirteen threads, ten findings

Five reviewers, and after grouping by finding rather than by reviewer: ten findings, every
one valid, every one reproduced red before it was fixed. Eight had the same shape — a route
the plane accepted and the provider would not — and one was silent, which makes it the worst
of the set.

1. **A mapping field became a constraint permitting only `{}`** (`dict[str, int]`). Pydantic
   spells it as a schema-valued `additionalProperties`; the tightening overwrote that value
   with `false`. No error, no rejected request — just a model asked to answer with an empty
   object. Refused at wiring now: the constraint cannot express dynamic keys.
2. **A non-object root was sent as the constraint** — a `RootModel` is a `BaseModel`, so the
   spec accepts one, and its array or scalar root reaches the provider as a request it
   rejects. Root-level unions with it.
3. **The constraint's name was assumed valid** because it is a Python identifier. Identifiers
   may be Unicode (`class Café`) and of any length, and a generic's `__name__` carries
   brackets; the provider takes ASCII word characters and 64 of them. The comment claiming
   otherwise was mine, and wrong.
4. **`protocol` and `output_mode` were unchecked literals** — `attrs` does not enforce those
   at runtime. The misspelled mode was the quiet one: not `"structured"`, so the encoder
   sent no constraint, and not `"text"`, so the decoder still expected JSON.
5. **A non-positive `max_output_tokens` and a negative `temperature`** went to the provider
   verbatim, where the rejection reaches the caller as a wire mismatch after the request.
   The batch cap already refused its bad value at wiring; these now do too.
6. **A template `str.format` cannot parse** raised a bare `ValueError` through a route
   resolve, because `Formatter().parse` is lazy and the iterator was walked outside the
   guard. A modifier the formatter rejects (`{text!z}`) passed wiring and failed on the
   first request; a dry render settles both, and the modifiers it accepts still work.
7. **A truncated completion was returned as an answer.** `finish_reason == "length"` was
   only noticed when the JSON failed to parse — so a completion cut at a token boundary
   became a validated `Out`, and truncated prose became the answer in text mode. Refused in
   both modes now, naming the knob.
8. **Nothing runs on a spent budget — except that it did.** Moving the budget check into the
   fan-out put it after the model-name resolution, so an expired call still ran an
   application's tenant resolver. That is a regression this branch introduced against the
   code's own promise that nothing ran and nothing was billed.
9. **A custom `WireProtocol` from before this branch raised `AttributeError`** before making
   any request. It is a public extension point, and absence of the two new members *is* the
   earlier shape's semantics — a whole batch per request, no usage — so it reads as that
   rather than failing.
10. **A stream reported its last chunk's tokens, not the stream's.** A span attribute is
    overwritten rather than accumulated, and `predict_stream` scores each chunk through its
    own call. Found by a nitpick, and the same defect as the one the self-audit found a
    level down — which is the lesson: the accumulator belonged to the port call all along,
    and fixing the inner case without asking who owns it left the outer one.

**Sabotage.** 14 mutations over the fix batch, 14 killed, each by the test written for it.
Two were re-run after their first form proved defective: one deleted a guard rather than
moving it, and one removed a `finally` wholesale where the point was recording *after* the
loop instead of within it.

Codacy's two medium complexity findings carry no specifics; the route config's post-init had
grown five unrelated guards and is now three named validators. The recursive schema walk is
left as it is — its branches are the shapes it checks.

## Review round 3 — one finding, in round 2's fix

A `Decimal` field crosses as a **string**: the encoder interpolates the same wire-safe
`model_dump(mode="json")` the rest of the plane uses. Round 2's probe held a real `Decimal`,
so `{amount:.2f}` passed wiring and the first prediction raised before any request was made
— the check was again testing a representation production never sees, one layer deeper than
the round before.

Fixed by making the probe mirror the dumped value rather than the declared type, which also
makes the refusal truthful: `{amount:.2f}` on a decimal genuinely cannot render through this
dialect, and an author now hears that at wiring instead of on first traffic. `{amount}` and
`{amount:>8}` keep working, and a test asserts what the request carries rather than only
that it was accepted.

The pattern across three rounds is one thing said three ways: **a validation probe is only
as good as its fidelity to what production does.** Empty string for every field, then a
typed Python value, then the dumped value — each fix moved the probe one step closer to the
encoder, and each intermediate step was wrong in a way only a reviewer's harness caught.

One mutation, killed by its own test.

## Review round 4 — the probe could not be saved

Three findings, and the first two are the same object seen from opposite sides: one reviewer
showed that a model with a custom `field_serializer` renders `{amount:.2f}` from a `Decimal`
field — so round 3's refusal was false — while the other showed that a field type the probe
had no entry for skipped validation entirely, letting `{when!z}` reach the encoder and raise
bare. A probe cannot satisfy both, because the declared type does not determine what the
formatter receives: a `Decimal` crosses as a string by default and as a number with a
serializer, same annotation either way.

So the guess is gone, and the check split along the line that actually holds:

- **A conversion** (`!z`) is valid or not regardless of the value, so it is refused at wiring
  for every field type — including the ones no stand-in could stand in for.
- **A format spec** is not checked at wiring at all. `encode_request` classifies a render
  failure as `configuration` rather than letting a bare `ValueError` out of the encoder, so
  the residual failure names the route and tells a caller to fix it rather than retry.

The third finding: none of the numeric route settings were type-checked before they were
bounds-checked, and every bad value was acted on somewhere it could not be — a string
reached a comparison, `True` passed as a number (it is an `int`), a fractional
`max_batch_size` reached `itertools.batched`. Fixed for all three fields, `max_batch_size`
included even though it predates this branch: same class, same post-init.

Four mutations, four killed.

**The rule worth keeping from these four rounds:** *a validation probe that invents its own
input is testing itself.* Where a check cannot see the real value, it should validate the
part that is value-independent and classify the rest where the value exists — not guess. Four
rounds went: empty string, typed Python value, dumped value, no value at all. Only the last
one is correct, and each earlier step looked right until a reviewer's harness ran it.

**Drift count: 0.**

## Review round 5 — one finding, the same seam

`{value:{width}}` binds `width` from the same instance, and slot discovery recorded only the
outer name — so a route whose input model did not declare `width` wired cleanly and failed on
every render. Format specs are now walked for their own replacement fields.

It lands exactly where round 4 drew the line, which is why the fix was a loop rather than a
rethink: **a field name is value-independent and belongs at wiring; a format spec depends on
what the model serializes and does not.** The nested field was a name hiding inside a spec,
so it was on the wrong side of that line by accident.

One mutation, killed. 235 tests in the inference battery.

## Review round 6 — one finding, in a public contract's prose

`slots` documents appearance order, and the worklist that round 5 used to pick up nested
format-spec fields deferred them: `{a:{b}} {c:{d}}` returned `("a", "c", "d", "b")`. Correct
as a *set*, which is all route validation reads — so nothing served wrongly — and wrong for
anything reading the property, which is public and says otherwise in its own docstring.

Fixed by walking depth-first, which also pulled the parse, slot and conversion rules into one
recursive helper instead of threading them through a loop with a stack beside it.

Worth noting what kind of finding this is: not a behaviour defect but a **documented contract
the implementation quietly stopped meeting**, in the same paragraph that documents it. The
fix for round 5 introduced it, which is the branch's fourth instance of a fix carrying its
own defect.

One mutation, killed. 14,334 unit tests pass.
